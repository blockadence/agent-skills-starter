# Skill Repository Instructions

Skills are organized into bucket folders under `skills/`:

- `engineering/`: engineering and code workflows
- `productivity/`: writing, communication, planning, and other productivity workflows
- `misc/`: useful but rarely promoted
- `in-progress/`: experimental skills
- `deprecated/`: retired skills retained for reference

Keep skills small and composable.

A producing skill owns substance, required sections, artifact structure, filenames, and semantic correctness.
A modifier skill owns cross-cutting expression constraints and must not silently change the producer's contract.

Prefer `SKILL.md` for process and invocation rules. Put stable, detailed background material in linked reference files.

When composing skills, make precedence explicit. User instructions come first, then the producing skill's semantic and structural contract, then modifier skills such as `in-my-voice`.

Avoid em dashes in repository prose. Rewrite the sentence naturally with a semicolon, colon, comma, parentheses, conjunction, or separate sentence.
