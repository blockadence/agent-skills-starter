# Engineering skill suite production readiness

The engineering documentation suite may be described as production-ready only when the mandatory gates below pass.

## Packaging

- [x] Skills use the repository's `skills/<bucket>/<skill-name>/SKILL.md` source layout.
- [x] Each new skill includes a human-facing README.
- [x] Every SKILL.md has `name` and `description` frontmatter.
- [x] Names are lowercase and hyphenated.
- [x] Repository prose follows repository style conventions.
- [ ] Validate discovery and invocation through the repository linker in a clean repository.

## Behavioral contracts

- [x] Each skill has one primary responsibility.
- [x] Producer, modifier, and audit ownership is explicit.
- [x] Outputs and prohibitions are explicit.
- [x] Audit findings route to an owning stage.
- [x] Source vocabulary and reader-facing vocabulary are treated separately.
- [ ] Exercise every skill against at least one positive fixture.
- [ ] Exercise every audit against at least one failing fixture.
- [ ] Verify wrapper retry and routing behavior in Claude Code.

## Acceptance fixtures

- [x] Canonical Evals spec located and read completely.
- [x] Evals stage-one source/explanatory/comprehension acceptance performed.
- [ ] Full Evals design package generated by linked skills.
- [ ] PR #175 code-review source recovered.
- [ ] PR #175 package generated by linked skills.
- [ ] Reviewer-variant truth-equivalence test passes.
- [ ] Known C4 collision is rejected by render QA.
- [ ] Fake-Java regression is rejected.
- [ ] Intent-leak regressions are rejected.
- [ ] BBB output starts with topic and pain and preserves progressive disclosure.

## Operational quality

- [ ] Run skills in fresh contexts to detect hidden dependence on the authoring conversation.
- [ ] Run at least one second design spec unrelated to Evals.
- [ ] Run at least one second PR review unrelated to PR #175.
- [ ] Confirm outputs are stable enough across repeated runs for human use.
- [ ] Document installation, invocation, intermediate artifacts, and troubleshooting.
- [ ] Version the suite and record compatibility assumptions.

## Claim rule

Until every mandatory unchecked item is complete, call this an implemented skill suite under acceptance testing.

When all mandatory gates pass, the production-ready claim is supported by installation, isolation, regression, and end-to-end evidence rather than prompt quality alone.
